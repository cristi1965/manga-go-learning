# Go 基础卷高效学习规格

## 目标

前 8 章服务于第一次系统学习 Go 的读者。学习者应先形成可运行的语言心智模型，再把同一概念映射到企业项目。企业案例不能替代基础语法教学。

## 必修顺序

1. `main`、打印、变量、基本类型和表达式。
2. `if`、`switch` 与布尔条件。
3. `for`、函数、参数和多返回值。
4. 数组、slice、map、string 与 rune。
5. struct、方法、指针和最小 interface。
6. error、`defer` 与第一份表驱动测试。
7. module、package、导出规则与真实 `internal` 边界。
8. goroutine、channel、取消和有界等待。

## 单章合同

每章只设一个基础主任务，并按以下顺序呈现：

1. 一句话说明这段程序解决什么。
2. 展示一份包含 `package`、`import` 和 `main` 的完整程序。
3. 先让学习者预测一个可见输出。
4. 运行原程序，立即看到输出。
5. 只修改一个值、条件或 TODO，再运行或测试。
6. 用一句话解释变化原因。
7. 最后才展示企业项目中同一概念的用途。

每章最多引入 3 个必须记住的新术语。类比、漫画、全局图、完整术语表和工程扩展默认放入“深入理解”，不得挡在首次运行前。

## 交互合同

- 初次进入章节时，一屏内必须看到完整主例和运行按钮。
- 基础主例和练习必须围绕同一个概念；不得出现正文讲 A、练习考 B、验收要求 C。
- 完成条件缩为：运行主例、固定测试通过、迁移题答对。
- 失败时先展示中文诊断：错误类型、当前行为、期望行为、下一步只改什么；原始 Go 日志放入折叠详情。
- 通过后自动记录本章基础进度，并给出明确的下一章入口。
- 控制流等必需内容属于主路线，不能只存在于选修补页。

## 工程映射

企业级内容保留，但只承担“为什么以后需要它”的作用。每章最多展示一个映射：

- 条件判断 → 请求校验。
- 循环与函数 → 批量处理和职责拆分。
- 集合 → DTO 与去重。
- struct/interface → 服务依赖边界。
- error/test → 失败关闭和回归证据。
- package/internal → 模块所有权。
- goroutine/channel/context → 有界并发与取消。

## 验收

- 8/8 基础主例由构建脚本执行 `go run` 或真实多文件 `go test`。
- 每章数据包含 `purpose`、`concepts`、`code`、`expectedOutput`、`changePrompt`、`explanation` 和 `enterpriseBridge`。
- 浏览器在桌面与手机宽度都能在进入章节后的首个工作区看到代码和运行按钮。
- 学习路线按 1-8 的依赖顺序推进，不要求先完成选修补页。
- 三类故意错误（语法、返回值、边界条件）都提供可行动反馈，并保留原始日志。
- 教学验收与工程 100 分报告分开记录；工程通过不能代替教学质量结论。
