# v20 连续编程学习体验

## 问题

现有页面把一课分成三个互斥长页。阶段切换会隐藏刚刚读过的依据并强制滚动；补页返回会丢失原位置；完成条件又横跨不可见阶段。内容上，Go 语法、后端契约、Wails、React 和 AI 概念在前置未建立时同时出现。

## 参考后的决策

- 采用 Go Tour 的单步前进和原地运行，不再使用三个互斥页。
- 采用 Exercism 的可见先修图和“测试通过才是掌握证据”，同时保留自由浏览。
- 采用 Codecademy 的稳定语义区：说明、编辑器、结果局部更新，不整页重建或跳位。
- 采用 Scrimba 的“讲解当场就能改”，说明和可编辑代码共享上下文。
- 采用 freeCodeCamp 的短讲解 -> 引导练习 -> 独立练习 -> 复习 -> 检查。
- 采用 Boot.dev 的基础与小型可见成果交替，但 Wails/React 不参与 Go 语法掌握判定。

完整来源与映射见 `specs/research/interactive-learning-patterns.md`。

## 新学习循环

每个微单元只新增一个知识点，主区保持三个稳定区域：

1. **这一步**：显示 `你已会 / 只学 / 学完可以`。
2. **当前代码**：预测、编辑、运行、结果就地完成。
3. **过关清单**：始终可见，每一个未完成项都能定位到对应控件。

原理、故事、图和补充术语放进“需要时再展开”，不再挡在练习之间。

## 滚动与焦点契约

- 切换章节时才定位到新章标题。
- 预测、运行、提示、还原、答题和完成检查不改变 `scrollY`。
- 运行结果使用 `aria-live`通知，不强制抢走编辑器焦点。
- 补页记录 `unit + anchor + scrollY`，返回时精确恢复。
- 移动端只保留一层粘性导航，所有定位使用统一 `--sticky-offset`。
- 连续 10 次小步操作不得出现回到页顶或被粘性栏遮挡。

## 内容先修主线

### Go

`main/输出 -> 变量/表达式 -> if -> for -> 函数单返回值 -> 多返回值/error -> array/slice/map/string -> struct -> 方法/指针 -> interface -> JSON -> package/module -> test -> goroutine -> WaitGroup/Mutex/race -> channel -> select/context`

### Wails + React

桌面壳始终可见，但默认折叠且不要求编辑。只在相应 Go 知识已学会后依次揭示：返回值 -> 方法 -> 导出 -> error -> 并发 -> context。React 仅使用生成绑定收集输入和展示结果。

### 后端

`net/http 最小 handler -> JSON -> httptest -> middleware 产生 Principal -> Service 授权 -> 存储 -> 并发/超时 -> 发布边界`，Gin 作为可选适配，不得与标准库练习混用契约。

### AI Agent

`可见 fake Agent 往返 -> 结构化决策 -> Provider -> Tool -> 循环/状态 -> 恢复/事件 -> RAG -> 审批 -> 评测 -> 总装`。里程碑必须放在所需概念之后，不得集中挂在第 16 章。

## 第一轮实施范围

1. 取消阶段互斥隐藏，重组为连续课流和按需深入区。
2. 移除同章交互中的强制滚动/抢焦点。
3. 加入始终可见的完成清单与精确缺项定位。
4. 补页返回恢复原单元和滚动位置。
5. 修正 AI 路线逆序，并把 8 个里程碑分配到概念之后。
6. 把零基础起步线并入主导航，第 1 章不再声称零前置。
7. 建立专项浏览器验收：滚动稳定、缺项定位、补页返回、桌面/移动端。

## 完成定义

- 当前单元所有主操作对滚动位置的意外变化不超过 8px。
- 完成失败时，页面显示可点击的第一缺项，不只显示 toast。
- 补页返回后恢复原章、原锨点与原滚动位置。
- 导航、上一单元、下一单元、URL 和先修图共用同一路线数据。
- 新建结构必须通过现有运行安全、79 单元桌面/移动端审计和新的学习流验收。
