# 连续讲解对话试点 · 2026-09-22

范围：chapter-1、supplement-go-real-test-file、supplement-go-ai-01。先在网页试读，再决定是否迁移其余单元。

设计：一个事件、一条因果线；2–3 个角色、4–6 轮，每轮可用2–3句解释完整动作。40字不再作为硬门槛；超过180字符提示分段，保留技术锚点及非空/重复检查。人物不为出场配额打断解释。笑点来自行为及结果，不用比喻解释另一个比喻。

参考：
- https://flashcat.cloud/blog/go-concurrency-visually-explained-channel/ ：同一个咖啡馆场景连续解释机制，借鉴组织方式，不复制台词。
- https://go.dev/doc/tutorial/add-a-test ：用可执行测试、预期结果和失败结果建立因果。

验收：源稿和生成数据一致；代码、题目、验收字段不变；技术事实人工检查；网页响应含新稿。工程旧报告不代表本轮教学通过。

任务：写三段试稿 -> 同步可持久化源文件 -> 定向生成 -> 核对非叙事字段不变 -> 网页取回核对。浏览器视觉验收和真人记忆效果分别记录。
