# v21 趣味性与连贯性重构

## 评审基线

三位独立 AI 辅助教学评审分别从零基础教学、叙事趣味和知识拓扑体验当前浏览器课程：

| 评审视角 | 总分 | 最关键问题 |
| --- | ---: | --- |
| 零基础编程教学 | 6.8 / 10 | 起步必修可被绕过；第 17 章目标和练习不是同一个对象 |
| 教学叙事与趣味 | 6.3 / 10 | 人物多在复述规则；故事没有直接触发后续行动 |
| 知识依赖与认知负荷 | 4.9 / 10 | M3/M4/M8 顺序错误；最终总装之后仍出现新必修能力 |

工程测试得分不计入这些教学分数。

## 目标

1. 每课用一个 30 秒内可读的具体冲突开场，立即提出可预测的问题。
2. 同一课的场景、示例、修改任务、独立练习和过关证据必须围绕同一技术对象。
3. 默认路线不能绕过零基础入口；有基础者通过诊断进入，而不是静默跳过。
4. 导航按钮显示真实目标名称，章节收尾与下一单元保持一致。
5. AI 路线按真实依赖排列，最终总装必须位于所有必修里程碑之后。
6. 故事只制造事故和误判；机制、规则、代码和测试各自承担不同职责，禁止重复朗读同一结论。

## 单课节奏

`事故钩子 -> 先预测 -> 运行观察 -> 只改一处 -> 解释一条规则 -> 独立测试 -> 下一课悬念`

- 钩子：两格、两句话，只呈现事故和一个可信误判。
- 预测：答案揭晓前记录学习者判断。
- 行动：代码和结果保持在同一视图，不跳页、不抢焦点。
- 反馈：先说实际与预期的差异，再给一条下一步。
- 悬念：只预告真实的下一单元，不引入尚未排进路线的术语。

## AI 必修拓扑

`Ch17 -> M1 -> M2 -> Ch18 -> M3 -> M4 -> Ch19 -> M5 -> M6 -> Ch20 -> Ch21 -> Ch22 -> M7 -> Ch23 -> M8 -> Ch24`

M3 先固定一次运行的租户与请求身份，M4 再限制这次运行可访问的工具路径；编号、依赖和页面顺序保持一致。

Wails + React 是独立的 Go 语法迁移路线：复用第 2、4、5、6、7、8 章的 Go 能力，让界面只调用和展示。它不是 AI 总装的前置条件，也不向主线额外引入一套 Wails 知识负担。

第 24 章是最终总装，完成条件必须包含 M1-M8、项目实验、失败恢复和 race 证据，不能只靠答题或单函数测试。

## 验收门槛

- 三位新上下文复评分别给出趣味性与连贯性，每位评审总分都不得低于 8.6；任一不足就按最高影响问题继续修改并复评。
- 路线脚本断言 M3 在 M4 前、M8 在 Ch24 前，Ch24 没有下一必修单元。
- starter 在运行前不显示改后答案；无主课进度时首页主按钮进入 starter。
- 第 17 章场景、练习和过关条件都围绕草稿、确认与禁止提前写账。
- 浏览器审计、企业项目审计和学习流审计继续通过。
