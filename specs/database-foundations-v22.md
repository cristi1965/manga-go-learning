# v22 数据库零基础学习路线

## 学习者与问题

目标学习者是熟悉 React、接口和 JSON，但几乎没有数据库经验的前端开发者。现有课程直接进入事务、幂等和缓存一致性，缺少表、行、列、主键、SQL 与 Redis 基础，导致第 11、12 章出现知识断层。

本路线先建立数据库直觉，再学习 MySQL 和 Redis，最后回到现有 Go 工程章节。Wails、AI Agent 与数据库路线彼此独立，不作为数据库语法的先修条件。

## 学习路线

`数据库基础 -> MySQL / SQL -> Redis -> Go 第 11 章事务 -> Go 第 12 章缓存`

### 第一阶段：数据库基础

1. 从 React 数组理解表、行和列。
2. 用主键稳定找到一条订单，理解它和数组下标的差别。
3. 区分字符串、整数、时间与 NULL。
4. 用订单和顾客理解一对多关系。
5. 把列表页的查询动作映射为 SELECT、WHERE、ORDER BY、LIMIT。
6. 设计一张可查询的订单表，完成阶段挑战。

### 第二阶段：MySQL 与 SQL

1. SELECT 指定列，避免无目的地读取全部字段。
2. WHERE 按租户与状态筛选。
3. ORDER BY 与 LIMIT 实现稳定列表。
4. COUNT、SUM、AVG 与 GROUP BY 实现看板统计。
5. JOIN 组合顾客和订单，区分 INNER JOIN 与 LEFT JOIN。
6. CREATE TABLE、PRIMARY KEY、NOT NULL 与 CHECK。
7. INSERT 新增订单并观察约束失败。
8. UPDATE / DELETE 使用主键和租户条件，避免整表误操作。
9. 事务与幂等把多步写入变成一次可靠提交，并衔接第 11 章。

### 第三阶段：Redis

1. SET、GET、EXISTS、DEL 与 key 命名。
2. EX、TTL、PTTL、PERSIST 与过期语义。
3. Hash 保存订单摘要。
4. Set 保存标签和去重集合。
5. Sorted Set 保存排行榜和时间序列索引。
6. INCR 实现原子计数器。
7. SET NX EX 建立一次性占位，理解它不等于完整业务幂等。
8. Cache Aside：数据库是真相源，提交后删除缓存；观察击穿、陈旧回填与 Redis 故障，并衔接第 12 章。

## 单课教学闭环

每课保持同一节奏，不滚动跳回页面顶部：

`前端类比 -> 看一条示例 -> 先预测 -> 只改一处 -> 运行 -> 解释结果 -> 一题检查 -> 下一课`

- 示例和练习始终使用同一家奶茶店的订单、顾客和商品数据。
- 首次出现术语时同时给出前端类比与数据库定义。
- 输出优先展示表格或 Redis 返回值，不只显示“通过”。
- 失败反馈指出哪条规则未满足，并给出最小下一步，不直接泄露完整答案。
- 每课草稿、预测、运行证据和完成状态都按单元保存。

## 运行证据边界

### MySQL

必修路线使用受信任的 MySQL 子集解析器和固定订单数据，检查语法结构、查询意图、危险写操作与预期表状态。页面必须明确标注这是教学验证器，不等于真实 InnoDB 的锁、隔离级别和并发行为。

真实 MySQL 8 集成作为增强证据：环境存在 MySQL 服务时可运行；不存在时不得用 SQLite 冒充，也不得阻塞 SQL 基础学习。

### Redis

环境存在 `redis-server` 时，每次练习启动隔离的临时实例，通过 RESP 协议执行白名单命令，展示真实返回值与 TTL 行为，结束后清理进程和目录。

环境不存在 Redis 时必须明确报告“真实 Redis 运行不可用”，不得退化为内存 Map 后仍宣称通过真实验证。

## 验收标准

1. 23 个单元均有前端类比、示例、预测、可编辑练习、运行反馈、检查题和明确下一步。
2. 数据库基础位于 MySQL 与 Redis 之前，依赖关系由自动化测试断言。
3. MySQL 验证器拒绝无 WHERE 的 UPDATE / DELETE，并能验证 SELECT、聚合、JOIN、建表与写入练习。
4. Redis 练习在本机真实 `redis-server` 上运行；进程和临时目录可追踪清理。
5. 桌面与移动浏览器通过入口、目录、预测、运行、答题、下一课和恢复进度流程。
6. 既有 Go、Wails 与 AI 学习路线回归通过。
7. 两个独立教学评审分别从零基础连贯性和互动有效性评分，均不低于 8.6 / 10；工程测试分数不计入教学分。
