# v24 连续学习流合同

## 问题

当前首页路线卡、章节顶部合同、五步锚点和过关清单同时在指挥学习。用户在页面下方点击“开始”或“去完成”时，容易被带回顶部或另一个锚点，不知道自己是换了课程，还是仅在当前页定位。

## 学习者

- 主要是熟悉前端、正在补 Go、数据库和 AI Agent 的学习者。
- 允许按自己的经验直接进入任意路线，不用完成证明换取阅读权限。

## 教学结构

### 首页

首页只是路线地图。每个按钮的文案、URL 和实际打开的单元必须一致。先修不足时只显示提示，不改写目标。

### Go / AI 课程

每课只保留三个当前任务：

1. **看现象**：具体问题与可运行例子同时出现。
2. **懂规则**：只替换左侧的必要解释，右侧代码保持在原位。
3. **动手过关**：显示独立练习、固定测试与验收状态。

任务切换只替换工作区内容，不滚动整页。桌面端两栏同时可见；移动端保留“讲解 / 代码与练习”视图，三任务切换器位于两个视图之外。不再提供会改变整页滚动位置的五步锚点。

### 过关

- 过关清单是状态列表，不是导航列表。
- 点击“检查本节是否过关”时，若有缺项，只显示唯一、明确的下一步，不自动滚动、切栏或改变 URL。
- 运行、答题、提示和恢复代码不改变整页滚动位置。

## 导航合同

- 跨单元导航：目录、搜索、首页路线、上一课、下一课、数据库衔接。必须更新 URL，打开文案所指的精确单元，并从该单元开头阅读。
- 单元内交互：运行、答题、展开、恢复、验收。默认不修改 URL 和整页滚动位置。
- 补页返回：回到来时的章节和视口锚点，不回章首。
- 首页和“Go 起步 6 步”是用户明确点击才进入的独立目标，不是其他路线的隐式重定向。

## 验收

- 无历史进度时，首页 Go、后端、AI 三阶段、Wails、MySQL 和 Redis 入口均打开自身声明的目标。
- 79 个 Go / AI 单元和 23 个数据库单元可通过目录打开，URL、标题和 active 目录一致。
- Go / AI 页不存在可点击的五步锚点；三任务切换前后 `scrollY` 变化不超过 8px。
- 缺项验收前后 `scrollY` 变化不超过 8px，hash 不变。
- 桌面双栏和移动两阶段均无溢出、焦点丢失和重复编辑器。
